# 08. 設計補強メモ・未決事項

構成段階で「今の技術方針を維持しつつ、後で迷わないために先に書いておく」内容。

## 1. 技術方針の判定（現状維持でよい）

| 領域 | 採用方針 | 判定 | 理由 |
|---|---|---|---|
| 手認識 | MediaPipe Hand Landmarker | **採用継続** | 21点・リアルタイム・Web実装が容易。自前学習は不要 |
| 仮想ペン先 | 幾何モデル A/B/C（拡張 D〜） | **採用継続** | 正解データなしでも比較検証できる。発明の核を分離できる |
| 描画 | Canvas 2D | **採用継続** | 直線 PoC に十分。WebGL は過剰 |
| 平滑化 | none / EMA / One Euro | **採用継続** | ブレと遅延を実験で比較できる最小セット |
| 描画ON/OFF | UIボタン | **採用継続** | 認識と操作判定の問題を分離できる |
| 独自AI学習 | 今回はやらない | **採用継続** | まず幾何で勝ち筋を見る |

結論: **今の技術スタックと段階分け（認識→推定→補正）はそのまま進めてよい。**  
変えるべきは「技術の種類」ではなく、実験結果に応じた **推定式・パラメータ・写像** である。

## 2. 仕様から補強した点（ドキュメント反映済み）

元仕様に対し、構成段階で次を追加・明確化した。

1. **モジュール分割**（Camera / Tracker / Estimator / Smoother / Mapper / Drawing）
2. **座標系の明示**（正規化 / カメラ画素 / Canvas）とミラー方針
3. **方式 D/E/F/G** を拡張候補として先行定義（必須は A/B/C）
4. **Grip score** をデバッグ用に用意（描画ゲートには使わない）
5. **キャリブはターゲット合わせ**を推奨（正解ペンなしでもオフセット取得可）
6. **実験メトリクスを Canvas 同一座標系で測る**ことを明記
7. **iPad 将来互換**のため、推定を純関数化する制約を追加

## 4. 主要リスクと今の対処

| リスク | 影響 | 今の対処 |
|---|---|---|
| Web成功 ≠ iPad成功 | 最終精度が出ない | 推定コアを移植可能に分離。掌接触は後段 |
| 方式Cが実感覚とずれる | 本命仮説が弱い | A/B/C比較を最初から入れる |
| 平滑化で遅延増 | 直線が遅れて描ける | One Euro を比較対象に含める |
| 照明・背景依存 | 認識成功率低下 | 実験条件を固定し、失敗条件を記録 |
| 個人差 | 他人で使えない | キャリブ ON/OFF 比較（実験5） |
