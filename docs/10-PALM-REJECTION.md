# 10. Palm Rejection と認識精度の限界

## 結論（先に）

**iPad / Safari / 通常の App Store アプリから、Palm Rejection（掌拒否）を正式に解除する手段はありません。**

精度向上は「拒否をオフにする」ではなく、

1. OS が通した接点を最大限使う
2. 途切れに強い判定にする
3. 反応しやすい当て方へ誘導する
4. 将来はカメラ等と融合する

で進める必要があります。

## 解除できない理由

| 層 | できること | できないこと |
|---|---|---|
| タッチコントローラ | 容量変化を測る | 小面積の側面接触を必ず拾う |
| iPadOS | 誤タッチを弾く | 第三者アプリ向けの「掌拒否オフ」API を提供しない |
| Safari (Web) | 渡された touch/pointer を受ける | 弾かれた接触を復活させる |
| HandPen AI | 受け取った点で推定・平滑化 | 来ていないイベントを捏造して本物の接触にする |

Apple Pencil 利用時の保護もシステム側の挙動で、Web から弱められません。  
検証時は **Apple Pencil を使わない／近くに置いて誤検出しない** 方が有利です。

## 本プロジェクトでの方針

- 「掌拒否解除」は目標にしない（不可能な前提を抱えない）
- **高感度モード**: 接触の途切れ・弱い接点・接触半径を活かして実用精度を上げる
- 学習・推定の入力は「物理接触」ではなく **OS が返した反応点** と明示する
- 将来の本命は、反応点 + 想定ペン先 +（必要なら）カメラ姿勢の融合

## ネイティブ化しても残る限界

Swift/UIKit の通常 API でも、システムが破棄したタッチはアプリに届きません。  
Private API や改造に依存する方法は App Store 配布と両立しにくいため、採用しません。
