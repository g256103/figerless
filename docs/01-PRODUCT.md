# 01. プロダクト方針

## 1. ビジョン

**ペンを物理的に持たなくても、ペンを握る動作と同じ手の形と動きで、自然な位置に線を描ける。**

最終形態は iPad 上の専用アプリを想定する。ただし最初から完成形を作らず、仮説検証に最適な Web カメラ PoC から始める。

## 2. なぜ Web から始めるか

| iPad 完成形を最初に作る場合 | Web PoC から始める場合 |
|---|---|
| 認識・推定・補正・UI・接触情報を同時に解く | 認識→推定→直線描画に集中できる |
| 前面カメラ＋掌接触の難易度が高い | 手全体が見える条件でモデルを比較できる |
| 実験サイクルが長い | ブラウザだけで試せる |

Web 版で「どの推定式が直線を引けるか」を先に見極め、その知見を iPad へ持ち込む。

## 3. 今回のスコープ（Phase 1〜3）

### In Scope

- Web カメラ起動
- MediaPipe による手ランドマーク取得
- 仮想ペン先の複数モデル比較（最低 A/B/C）
- 平滑化（なし / EMA / One Euro）
- Canvas への線描画
- 描画 ON/OFF（**ボタン操作**）
- 簡易キャリブレーション
- 直線ガイド実験用 UI
- デバッグ表示（座標・方式・FPS）

### Out of Scope（今回やらない）

- ジェスチャーによる描画開始/終了
- 曲線・円・塗りつぶし・ブラシ表現
- AI モデルの独自学習・ファインチューニング
- Apple Pencil による正解データ収集
- iPad 専用アプリ / 画面接触センサ統合
- マルチユーザー同期・保存・共有

## 4. MVP 完成条件

次をすべて満たしたら Web MVP 完成とする。

- [ ] Web カメラを起動できる
- [ ] ペン握り形の手を安定して認識できる
- [ ] 手首・指の位置をリアルタイム取得できる
- [ ] 仮想ペン先を計算できる（方式切替可能）
- [ ] 手を動かすと画面上の線が追従する
- [ ] 水平・垂直・斜めの直線を描ける
- [ ] 描画結果を画面上で確認できる
- [ ] 線の消去ができる

## 5. 暫定成功基準（実験目標）

| 指標 | 最初の目標 | 備考 |
|---|---|---|
| 手の認識成功率 | 95% 以上 | 実験1 |
| 直線描画の完了率 | 90% 以上 | 実験3 |
| 平均位置誤差 | 画面幅の 2% 以内 | ガイド線との比較 |
| 描画遅延 | 100ms 以内 | 主観＋簡易計測 |
| 直線方向 | 水平・垂直・斜めの3方向 | すべて描画可能 |

※ これらは保証値ではない。実測後に現実的な基準へ調整する。

## 6. ロードマップ

| Phase | 内容 | 目標 | 状態 |
|---|---|---|---|
| 1 | Webカメラで手を認識 | 手の位置を取得 | 設計中 |
| 2 | 仮想ペン先を計算 | 座標を推定 | 設計中 |
| 3 | 直線描画 | 直線を引ける | 設計中 |
| 4 | 個人別キャリブレーション | 個人差を補正 | 後続 |
| 5 | 曲線・円の描画 | 自由曲線に対応 | 後続 |
| 6 | iPad 専用アプリ化 | 前面カメラで認識 | 後続 |
| 7 | 画面接触情報の統合 | 掌・接触位置を活用 | 後続 |
| 8 | 描画精度の改善 | イラスト制作を目指す | 後続 |

## 7. ユーザー操作の最終イメージ（将来）

1. 実際のペンやタッチペンは持たない
2. 親指・人差し指・中指でペンを握るときとほぼ同じ形を作る
3. 手のひらを画面に置く（iPad 完成形）
4. 手首や手全体を動かす
5. カメラが手の位置・角度・関節を認識する
6. 推定モデルが仮想ペン先座標を計算する
7. その座標で画面に線を描く

**重要:** 人差し指の先端をそのままカーソルにするのではなく、**ペンを握っていると仮定した仮想ペン先**を推定する。

## 8. Web 版での操作方針（今回）

- 描画開始/停止は **UI ボタン** で行う
- 描画中はペン握り形を維持し、手首・手全体を動かす
- ジェスチャー判定は Phase 3 完了後に検討する

理由: 認識精度と操作判定を同時に解くと、失敗原因が切り分けられないため。
