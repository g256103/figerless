# 04. 仮想ペン先の推定（コア仕様）

このドキュメントは HandPen AI の中核である **推定層** を定義する。  
認識結果（landmarks）から、実際にペンを握っていると仮定したときのペン先座標 \(P_{\mathrm{pen}}\) を求める。

## 1. 設計原則

1. **指先カーソル化をゴールにしない**  
   方式A（人差し指先端）はベースライン比較用。本命は握りを仮定した推定。
2. **最初は学習なしの幾何モデル**  
   正解ペン先がないため、教師あり学習は後段。まずは比較可能な式を並べる。
3. **純関数として実装する**  
   `estimate(mode, landmarks, params) -> {x,y}`  
   副作用・DOM・Canvas に依存しない。
4. **Web で勝ち筋を見つけ、iPad へ移植する**  
   カメラ固有のマジックナンバーを式の中核に埋め込まない。

## 2. 記号定義

| 記号 | 意味 | Landmark |
|---|---|---|
| \(P_{\mathrm{wrist}}\) | 手首 | 0 |
| \(P_{\mathrm{thumb}}\) | 親指先端 | 4 |
| \(P_{\mathrm{index}}\) | 人差し指先端 | 8 |
| \(P_{\mathrm{indexMCP}}\) | 人差し指付け根 | 5 |
| \(P_{\mathrm{middle}}\) | 中指先端 | 12 |
| \(P_{\mathrm{middleMCP}}\) | 中指付け根 | 9 |
| \(G\) | 仮想握り位置 | 計算値 |
| \(v\) | ペン軸方向の単位ベクトル | 計算値 |
| \(L\) | 仮想ペン長さ | パラメータ / キャリブ |
| \(P_{\mathrm{pen}}\) | 仮想ペン先 | 出力 |

座標は原則 MediaPipe 正規化座標（必要なら z も保持。2D描画は x,y）。

## 3. 比較方式（必須実装）

実験2で切り替えて比較する。**最初から A/B/C を UI で切替可能にする。**

### 方式 A — 人差し指先端（ベースライン）

\[
P_{\mathrm{pen}} = P_{\mathrm{index}}
\]

- 最も単純
- 「ペンなし描画」の直感とは異なるが、認識安定性の下限確認に必要

### 方式 B — 親指と人差し指の中間（握り位置）

\[
G = \frac{P_{\mathrm{thumb}} + P_{\mathrm{index}}}{2}
\]
\[
P_{\mathrm{pen}} = G
\]

- 仮想的なグリップ点そのものを描画点にする
- ペン先より手前に出やすい可能性が高い

### 方式 C — 握り位置 + 手首方向への延長（本命の第一候補）

\[
G = \frac{P_{\mathrm{thumb}} + P_{\mathrm{index}}}{2}
\]
\[
v = \frac{G - P_{\mathrm{wrist}}}{\|G - P_{\mathrm{wrist}}\|}
\]
\[
P_{\mathrm{pen}} = G + L \cdot v
\]

| パラメータ | 意味 | 初期案 |
|---|---|---|
| \(L\) | 握り位置からペン先までの長さ | 正規化空間で 0.08〜0.20 を探索 |

#### 方式 C の限界（最初から認識しておく）

- 実ペンの軸は「手首→握り」と完全一致しない
- 手首回旋・掌の傾きで誤差が増える
- それでも「延長した先」という仮説の第一弾として十分

## 4. 拡張方式（実装優先度つき提案）

構成段階のため、C の次に試す候補を先に定義しておく。  
**MVP 必須ではないが、インターフェースは最初から開いておくと実験が速い。**

### 方式 D — 中指を含めた握り位置（推奨・次点）

三指でペンを支える前提に近づける。

\[
G = \frac{P_{\mathrm{thumb}} + P_{\mathrm{index}} + P_{\mathrm{middle}}}{3}
\]
\[
P_{\mathrm{pen}} = G + L \cdot v,\quad
v = \frac{G - P_{\mathrm{wrist}}}{\|G - P_{\mathrm{wrist}}\|}
\]

または重み付き:

\[
G = w_t P_{\mathrm{thumb}} + w_i P_{\mathrm{index}} + w_m P_{\mathrm{middle}}
\]

初期案: \(w_t=0.4,\; w_i=0.4,\; w_m=0.2\)

### 方式 E — MCP 基準のペン軸（掌接触将来を意識）

先端は隠れやすく、付け根（MCP）は残りやすい、という将来の iPad 条件を先取りする。

\[
G = \frac{P_{\mathrm{indexMCP}} + P_{\mathrm{middleMCP}}}{2}
\]
\[
v = \frac{G - P_{\mathrm{wrist}}}{\|G - P_{\mathrm{wrist}}\|}
\]
\[
P_{\mathrm{pen}} = G + L \cdot v
\]

Web でも、先端ノイズが大きいときに E が安定する可能性がある。

### 方式 F — 指の向きを軸にする

手首基準ではなく、人差し指の骨方向をペン軸に近似する。

\[
v = \frac{P_{\mathrm{index}} - P_{\mathrm{indexMCP}}}{\|P_{\mathrm{index}} - P_{\mathrm{indexMCP}}\|}
\]
\[
G = \frac{P_{\mathrm{thumb}} + P_{\mathrm{index}}}{2}
\]
\[
P_{\mathrm{pen}} = G + L \cdot v
\]

「握って前方へ出す」感覚に近いが、指を曲げた瞬間に軸がブレやすい。

### 方式 G — オフセット付き C（キャリブ前提）

方式 C に個人オフセットを足す。

\[
P_{\mathrm{pen}} = G + L \cdot v + O
\]

\(O\) はキャリブレーションで決める 2D オフセット。

## 5. 握り形の判定（Grip Pose）

描画ボタンとは別に、「今ペン握り形になっているか」をスコア化しておくと実験が楽。

### 簡易スコア案（学習なし）

次のような特徴量を組み合わせる。

1. 親指先端と人差し指先端の距離 \(d_{4,8}\) が一定範囲
2. 中指先端が人差し指先端の近くにある \(d_{8,12}\)
3. 人差し指・中指がある程度曲がっている（先端と MCP の距離が伸びきっていない）
4. 薬指・小指が曲がっている（任意）

出力: `gripScore ∈ [0,1]`

MVP では **描画ゲートには使わない**（ボタンで制御）。  
デバッグ表示と、将来のジェスチャー開始の種にする。

## 6. 平滑化との接続

推定出力 \(P_t\) に対し、平滑化後 \(S_t\) を描画に使う。

### EMA

\[
S_t = \alpha P_t + (1-\alpha) S_{t-1}
\]

- \(\alpha\) 大: 追従速い、ブレ残る
- \(\alpha\) 小: 滑らか、遅延増

### One Euro Filter

低速時は強く平滑、高速時は追従を上げる。直線実験の遅延対策として有望。

実装時は x/y 独立にフィルタを持つ。

## 7. 異常値処理

| 条件 | 対応 |
|---|---|
| \(\|G - P_{\mathrm{wrist}}\|\) が極端に小さい | 方式C/D/E をスキップし、前回値 or 方式Bへフォールバック |
| landmark 欠損 | そのフレームは未検出扱い |
| 1フレームで大きなジャンプ | 平滑化前にクランプ（任意、実験4で可否判断） |


`meta` に `G`, `v`, `gripFeatures` を入れるとデバッグが容易。

## 9. 検証で見たい問い

1. A より C の方が「意図した位置」に近いか？
2. B は握り直感に合うが、ガイド線追従では不利か？
3. D（三指）は個人差に強いか？
4. E（MCP）は先端隠れ耐性の片鱗があるか？
5. L と平滑化のどの組み合わせが、誤差と遅延のバランスが良いか？

これらの答えはコードの美しさではなく、[06-EXPERIMENTS.md](06-EXPERIMENTS.md) の数値で決める。
